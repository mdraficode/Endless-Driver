## Responsibility

DOM UI for diagnostics, pause/home navigation, saved gameplay/display preferences, asset credits, startup feedback, HUD elements, and the mobile touch overlay. UI reads snapshots and sends user actions through application callbacks; it never drives physics or rendering directly.

## Implemented

- `PauseMenu.ts` — keyboard- and touch-accessible Resume/Restart, overview, Spawn Location, Gameplay Options, Graphics, Car Model, Controls & Help, and final Credits navigation. The menu can be opened from the right-corner button, `P`, or `Escape`; it stops/resumes the running application and rebuilds in-page on restart/apply to avoid a fullscreen-breaking navigation.
- `CreditsPanel.ts` — manifest-driven attribution dialog opened from the final menu entry, with focus return to the invoking item.
- `StartLocationSelector.ts` — URL helper preserves unrelated query options while switching spawn; spawn choice is now presented from the menu rather than a separate HUD picker.
- `LoadingScreen.ts` — monotonic reported startup stages plus a separate 50 ms timer-driven visual fill that follows reported progress without snapping and advances at 6–8 percentage points per second before readiness. The visible counter is plain `NN%` with no “Est.” prefix. Estimated progress stops at 99%, displaying “Still working…” with a sheen until the true first playable frame arrives; the remaining fill then advances at 12 points per second, and gameplay is revealed only when the bar reaches 100%. Elapsed time is integrated across delayed timer ticks; reduced-motion mode suppresses decorative sheen, not functional progress motion. The progress fill now uses a visible 3.2-second breathing pulse and a gentler 5.4-second reduced-motion pulse, without affecting percentage arithmetic or readiness. Startup foliage generation yields between single chunks so timer callbacks and paints can run during preparation. The pulse/fullscreen correction was pushed at `4ac1b6c`; full `npm run check` passed at `b34c280`. No Play gate.
- `FullscreenOnStart.ts` and `LandscapeFallback.ts` — best-effort fullscreen requests, retried from document-capture mouse/touch/pen pointer activation, any page click, keyboard activation, and legacy `touchend` where Pointer Events are unavailable. Touch/pen prefer `pointerup`, with click as a fallback. Native landscape lock and the page-level landscape fallback remain best-effort; browser gesture policy and OS rotation settings cannot be overridden.
- `Minimap.ts` — destination map HUD parented to the app rotation/stacking context and hidden while the pause/home menu is open.
- `DiagnosticsOverlay.ts` — full-screen live FPS/frame-time, viewport, render, scene, vehicle, weather and surface-response report; responsive non-scrolling metric grid sits above the minimap/touch HUD, updates at the application's HUD interval, and closes with × or F2.
- `TouchControls.ts` — multi-touch steering, pedals and utility buttons; the pause button remains at the upper-right without overlapping the utility row.

## Preferences with gameplay effects

- `game-preferences.ts` validates and persists graphics tier, city traffic intensity, player-car model, startup camera, and steering response. Invalid or blocked storage safely falls back to defaults.
- Graphics tiers resolve at startup; traffic intensity changes Aohara's moving-vehicle budget; the selected car model swaps the imported Generic Sport Coupé or project-authored Kaminari GT Roadster in place without rebuilding the renderer; camera, traffic and steering options still use Apply & Restart.
- Credits remain the last menu item and retain the existing required CC BY 4.0 attribution.
